# Two-pass audit — 2026-08-21

This record freezes the scientific/algorithmic audit before server execution. Runtime integration on the actual GPU hosts is still required; the points below are the non-runtime invariants that were checked and hardened.

## Pass 1 — forward audit: data -> intervention -> training -> evaluation -> verdict

Critical fixes:

1. **True-control provenance.** False friends and true/common cognates are loaded from their separate Stingray sources. True controls are never inferred from the FF table.
2. **Strict lexical targets.** Primary targets must be the exact same written form and the same single tokenizer id both sentence-initially and after whitespace.
3. **Exact occurrence mask.** Tokenizer offsets identify standalone lexical occurrences. A matching subword id inside another word is not manipulated.
4. **Pair-level holdout.** If a target-containing OPUS pair is selected for evaluation, both translations are excluded from training.
5. **Post-filter mask cleanup.** Candidate targets that fail the evidence gate have their training masks cleared.
6. **Step-0 identity.** Every alias row is copied from its base row in both conditions; paired shared/split seeds start tensor-identically.
7. **Equal output normalization.** Reserved aliases do not increase the effective output choice set. Shared masks all aliases; split uses one-in/one-out base<->alias substitution only for exact DE target labels.
8. **Optimizer-update semantics.** `max_updates` and checkpoint numbers mean optimizer updates, not microsteps.
9. **One GPU per run.** Scientific parallelism is across independent seed/condition jobs; no DDP/Slurm assumptions remain.
10. **Full metric windows.** Gate-1 evaluation keeps only target occurrences with the complete prespecified pre/post windows.
11. **Statistical unit.** Occurrences -> contexts -> word×seed×language -> equal EN/DE weighting -> crossed word×seed bootstrap.
12. **Frequency adjustment.** FF specificity is checked after total-frequency and EN/DE imbalance adjustment.
13. **Frozen provenance.** Data fingerprint, config hash, Git commit, initialization fingerprint, effective batch, terminal update and paired GPU model are recorded/checked.

## Pass 2 — reverse audit: claimed conclusion -> required evidence -> code invariant

The desired positive claim is not "false friends are hard." It is a causal dissociation caused by lexical sharing.

A Gate-1 PASS therefore requires the conjunction of:

- FF shared-minus-split `form_nll < 0` with CI below zero;
- raw FF post-target cost positive;
- localized FF post-target cost `(delta_post - delta_pre) > 0`;
- FF localized cost larger than true-cognate control;
- that specificity survives prespecified frequency adjustment;
- >=80% paired seeds have the expected directions;
- pre-target divergence remains small;
- >=10 FF and >=10 true-cognate lexical types and all five paired seeds;
- exact shared/split evaluation coverage;
- identical data/config/code/effective-batch/terminal-step provenance and paired initialization fingerprint;
- same GPU model within each paired seed.

`post_nll` is treated as meaning-sensitive contextual integration, not direct proof of a wrong dictionary sense. Explicit Stingray likelihood evaluation is confirmatory only after this causal gate survives.

## Path-dependence hardening

A later path gate is valid only if earlier gates survive. EN-first and DE-first use independent deterministic per-language RNGs, constant LR, zero warmup, equal language exposure, and an optimizer reset before the identical balanced tail. The later estimand is a sharing-specific order interaction, not a generic recency/forgetting effect.
